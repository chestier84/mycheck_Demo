1️⃣ Railway (Lo Más Fácil - Recomendado)

✅ Recomendado para Datafix: Railway es ideal para tu proyecto porque maneja docker-compose automáticamente.

Paso 1: Preparar Repositorio GitHub

1 Crea un repositorio en GitHub
git init git add . git commit -m "Datafix Oracle - Ready for Cloud" git branch -M main git remote add origin https://github.com/TU_USUARIO/datafix-oracle.git git push -u origin main

Paso 2: Registrarse en Railway

2 Ve a railway.app y crea cuenta con GitHub
  1. Haz clic en "Deploy Now"
  2. Selecciona tu repositorio
  3. Railway auto-detecta docker-compose.yml

Paso 3: Configurar Variables de Entorno

3 En Railway Dashboard → Add Environment Variables
ORACLE_PWD=OraclePwd1 PYTHONUNBUFFERED=1

Paso 4: Deploy Automático

4 Railway despliega automáticamente
  • Cada push a GitHub → Auto-deploy
  • URLs públicas generadas automáticamente
  • Los logs están disponibles en el dashboard
✅ Ventaja: Todo automático, perfecto para MVP y desarrollo.

2️⃣ Docker Hub + AWS ECS (Profesional)

Paso 1: Subir Imágenes a Docker Hub

1 Login en Docker Hub
docker login # Username: tu_usuario_dockerhub # Password: tu_token
2 Etiquetar Imágenes
# Backend docker tag backend-backend:latest tu_usuario/datafix-backend:latest docker tag backend-backend:latest tu_usuario/datafix-backend:v1.0 # Frontend docker tag nginx:alpine tu_usuario/datafix-frontend:latest
3 Subir a Docker Hub
docker push tu_usuario/datafix-backend:latest docker push tu_usuario/datafix-backend:v1.0 docker push tu_usuario/datafix-frontend:latest
ℹ️ Ver imágenes: docker images

Paso 2: AWS ECS (Elastic Container Service)

4 En AWS Console → ECS → Create Cluster
  1. Cluster name: "datafix-cluster"
  2. Infrastructure: "AWS Fargate"
  3. Create Task Definition desde Docker Hub images
  4. Create Service
  5. Asignar Load Balancer (para alto tráfico)
⚠️ Nota Oracle: AWS ECS no es ideal para bases datos con estado. Usa AWS RDS para Oracle o Docker en EC2.

Paso 3: RDS para Oracle (Base de Datos Gestiona)

5 AWS Console → RDS → Create Database
  1. Engine: Oracle Database Express Edition
  2. DB Instance: db.t3.small (costo ~$20/mes)
  3. Storage: 20 GB
  4. Crear
✅ Ventaja: Escalable, profesional, backups automáticos.

3️⃣ Google Cloud Run (Serverless)

Paso 1: Preparar Dockerfile

1 Asegúrate de que tu Dockerfile escucha en puerto 8080
EXPOSE 8080 CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8080"]

Paso 2: Build y Push a Google Artifact Registry

2 Desde tu PC
gcloud auth configure-docker docker build -t gcr.io/TU_PROJECT_ID/datafix-backend:latest . docker push gcr.io/TU_PROJECT_ID/datafix-backend:latest

Paso 3: Deploy en Cloud Run

3 Google Cloud Console → Cloud Run → Create Service
  1. Container image: tu imagen de Artifact Registry
  2. Allow unauthenticated invocations: SÍ (para API pública)
  3. Create
  4. Google genera URL pública automáticamente
⚠️ Limitación: Cloud Run es stateless. No guarda datos entre reinicios. Para base de datos, usa Cloud SQL.

Paso 4: Cloud SQL para Oracle

4 Google Cloud Console → Cloud SQL → Create Instance
⚠️ Google Cloud NO soporta Oracle en Cloud SQL. Solo MySQL, PostgreSQL, SQL Server.
Alternativa: Usa PostgreSQL (más barato, $10-30/mes) o Oracle en Compute Engine.
✅ Ventaja: Gratuito hasta cierto uso, muy económico para startups.
