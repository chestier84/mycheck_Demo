Red interna

Docker compose default network — todos los servicios se resuelven por nombre de servicio como DNS (`backend`, `oracle-xe`, `frontend`).

Por qué un solo origen

El navegador habla con localhost:8080 y nginx hace proxy de /api/* a backend:8000. Esto elimina CORS sin tocar headers.

Truco de host

ORACLE_HOST_OVERRIDE traduce localhost que envía el navegador al hostname interno oracle-xe. Sin esto, el backend resolvería localhost a sí mismo.

Volúmenes y montajes

oracle-data volumen named — persiste /opt/oracle/oradata entre reinicios. Sobrevive a docker compose down. Se borra solo con down -v.
./init bind mount → /opt/oracle/scripts/startup. Ejecuta 01_create_appuser.sql la primera vez que arranca Oracle.
../datafix_oracle.html + ./nginx.conf bind mounts read-only en nginx:alpine. Editar el HTML local refresca al recargar.
Detalle a no romper

El campo de password en el JSON debe llamarse password, no pass. Pydantic XEConfig lo exige y devuelve HTTP 422 si falta.

Healthcheck importa

El backend tiene depends_on: oracle-xe { condition: service_healthy }. Por eso espera ~3-5 minutos hasta que Oracle pasa el sqlplus check antes de arrancar.
